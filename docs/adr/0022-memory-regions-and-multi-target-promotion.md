# 记忆区域和多目标晋升

## 状态

已接受（2026-10-24）。

## 背景

个人记忆天然分层。用户记忆跨项目，专题记忆对应技能或课程，项目记忆对应具体项目，非项目会话需要短期记忆区域。

把用户记忆当作所有项目记忆的存储父节点会产生所有权、生命周期、权限和冲突歧义。项目记忆不是用户记忆的子集。

## 决策

1. 记忆区域分为用户、专题、项目和会话四类。
2. 用户记忆区域使用 `space=user`。专题记忆区域使用 `space=topic:<id>`。项目记忆区域使用 `space=project:<id>`。会话记忆区域使用 `space=chat`，并用会话级 `session` 区分每次会话。
3. 存储层所有区域是 peer spaces。记忆区域树只是管理台导航和召回策略，不是存储所有权或权限继承。
4. 项目记忆区域是绑定项目根目录的专题区域。专题记忆区域不要求项目根目录。
5. 默认召回：项目会话只查当前项目空间；专题会话只查当前专题空间；非项目、非专题会话查用户空间和当前会话空间。跨区域召回必须显式请求。
6. 自动晋升是多目标的。会话、项目和专题记忆可以晋升到用户记忆或专题记忆。项目特定内容保留在项目记忆。临时内容保留在会话记忆或按保留策略清理。
7. 晋升目标：稳定个人事实到用户记忆；可泛化技能或课程知识到匹配的专题记忆；项目特定事实留在项目记忆；无法确定目标时保留原区域。
8. 晋升证据：明确用户陈述且置信度高，或至少两个独立来源重复出现。敏感内容和冲突事实不自动晋升。
9. 晋升创建带 `provenance` 的新单元，源单元保留。晋升必须幂等、可审计、可更正和可遗忘。
10. 会话记忆默认保留 30 天，可归档或遗忘。晋升后的单元不受会话清理影响。
11. 跨区域召回使用显式选中的区域。结果按来源区域分组，并受预算上限约束。
12. 预算默认值：总预算 10K tokens；用户记忆最多 30%；每个选中专题或项目最多 20%；图扩展最多 20%；来源和结构信息最多 10%。预算可配置。
13. 审计使用持久化 SQLite 审计存储，重启后仍可查询。
14. 管理台提供 Markdown 导出。导出是只读视图，不提供导入，也不构成第二套真源。
15. 本地守护进程只监听回环地址。产品外壳使用 API Key 鉴权，mem2.0 在进程内使用可信本地安全上下文。

## 后果

- ADR 0021 中“项目、用户和会话到 Scope 的映射”不再未决，由本 ADR 决定。
- 项目或专题区域归档、删除后，已晋升单元仍然存在，来源引用可能指向已归档的源单元。
- 会话记忆需要保留清理任务，避免无限增长。
- 跨区域召回需要验证 mem2.0 的 spaces 扩展、来源标记和预算裁剪。
- 自动晋升需要验证分类、证据、幂等、冲突和敏感性处理。

## 替代方案

- 用户记忆作为项目记忆的存储父节点：被拒绝。所有权、生命周期和权限语义不清。
- 所有内容都晋升到用户记忆：被拒绝。会污染全局记忆。
- 非项目会话直接写用户记忆：被拒绝。会话临时内容会污染全局记忆。
- 默认全量跨区域召回：被拒绝。项目隔离和预算不可控。
