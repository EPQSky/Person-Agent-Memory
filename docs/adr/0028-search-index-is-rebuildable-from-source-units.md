# 检索索引可由源单元重建

KV 存储中的记忆单元是唯一源数据。向量行与全文行是它们的派生物，只服务检索。两者可能不一致：进程被强杀、段文件损坏或写入中断时，索引行会丢失，而记忆本体仍在。此时记忆被保存却永远无法召回，系统也不会报错。

系统必须探测这种漂移并自愈。启动后立即执行一次探测，此后每 10 分钟重复一次。探测按作用域批量读取逻辑 id，只取 `logical_id` 字段，不搬运向量。缺失的单元用正常索引构建器重建，写入模式为仅检索索引，不重复写正排本体。单个单元最多尝试 5 次；仍失败时记录告警并跳过，直到进程重启。

不采用「检索时跳过缺失单元」的做法，因为那会把数据损坏变成静默的召回缺失。不采用「整库重建」的做法，因为成本随库规模增长，而损坏通常是局部的。也不采用「写入失败即回滚记忆本体」的做法，因为记忆本体是证据，丢失不可恢复，而索引可以重建。
