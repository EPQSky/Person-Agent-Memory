# 02 — 用户级服务与 Codex 插件注册

**What to build:** `setup` 在核心初始化之后注册 Codex 插件、生成并启用用户级 systemd 服务、启动守护进程、等待认证健康检查成功，然后输出安装摘要（服务状态、Web 地址、密钥文件位置、常用管理命令）。重复执行收敛到当前版本，不产生重复的服务定义或插件记录。

**Blocked by:** 01 — 用户初始化核心.

**Status:** done

- [x] 生成的用户级服务定义与既有安装器模板语义一致：同一守护进程命令、同一目录参数、同一重启策略
- [x] 服务被启用并立即启动，随用户登录自动启动
- [x] Codex 插件注册收敛，重复执行不产生重复记录
- [x] 健康检查失败时输出诊断命令与非零状态，不报告成功
- [x] 安装摘要包含服务状态、Web 地址、密钥路径与启停和日志命令，且不泄露密钥正文
- [x] 测试断言服务定义的目录参数、端口与重启策略与既有安装器模板一致；守护进程路径按渠道前缀不同，不要求内容一致
- [x] `setup --uninstall` 移除用户级服务定义并停止禁用服务、移除插件注册；可选清除平台状态；永不删除记忆库
- [x] 文档化卸载顺序：先运行 `setup --uninstall`，再移除发行包；残留服务定义会因程序文件缺失而反复启动失败
