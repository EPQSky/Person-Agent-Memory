# 05 — 平台编辑与隔离 Git 历史

**What to build:** 让用户在 Web 平台中编辑权威 Markdown、预览保存差异并查看本地 Git 历史，使每次完成的修改或恢复形成隔离的原子提交，同时不触碰包含记忆目录的项目仓库。

**Blocked by:** 04 — 导入 Markdown 并完成直接检索

**Status:** done

- [x] Web 提供文档树、Markdown 源码编辑、渲染预览和保存前差异，且长文档和代码块可正常查看与修改。
- [x] 每次完成的单文档编辑通过原子文件替换落盘，并形成一个只包含该记忆变更及必要清单更新的 Git 提交。
- [x] 每个记忆库默认使用隔离的 sidecar Git 仓库；记忆目录位于已有项目仓库内时，项目仓库索引、分支和工作区不被平台修改。
- [x] 复用已有专用记忆仓库必须由用户显式授权，发现 `.git` 本身不会触发提交。
- [x] Git 只跟踪权威 Markdown、遗忘标记和可移植目录清单；状态库、索引、Graph、Inbox、候选、日志、缓存和凭据被排除。
- [x] Web 可以查看提交列表和逐行差异，并通过新的恢复提交还原旧版本，不执行 reset、rebase 或历史重写。
- [x] 提交使用固定平台身份，平台操作记录另行保存操作者类型和操作来源。
- [x] 平台不自动配置 remote，也不执行 pull 或 push；Docker 验收证明包含项目仓库在整个流程前后保持不变。
