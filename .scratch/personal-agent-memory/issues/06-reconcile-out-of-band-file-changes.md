# 06 — 处理带外文件变更

**What to build:** 让平台检测绕过管理界面的 Markdown 编辑、移动和删除，暂停受影响内容的自动接纳，并让用户通过三方差异明确导入外部版本或恢复平台版本。

**Blocked by:** 05 — 平台编辑与隔离 Git 历史

**Status:** done

- [x] 外部编辑、移动或删除已跟踪 Markdown 后，平台在有限时间内标记带外变更并在 Web 显示受影响文档。
- [x] 检测到带外变更后，平台不静默创建 Git 提交，也不把未确认版本传播到向量或 Graph 派生数据。
- [x] 当平台基线与外部版本存在差异时，Web 展示 base、平台版本和带外版本的三方比较。
- [x] 用户可以确认导入带外版本，操作形成新的原子 Git 提交并刷新直接检索来源版本。
- [x] 用户可以拒绝带外版本并恢复平台版本，操作同样形成可审计的新提交。
- [x] 外部和平台同时修改同一内容时不自动合并；用户必须提供最终内容才能结束冲突状态。
- [x] 未受影响文档继续可检索和编辑，一个文件的冲突不会冻结整个记忆库。
- [x] Docker 验收覆盖编辑、移动、删除、同时修改、确认导入、拒绝恢复及进程重启后的待处理状态恢复。
