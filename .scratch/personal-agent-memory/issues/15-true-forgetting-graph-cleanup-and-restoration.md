# 15 — 真正遗忘、图清理与恢复

**What to build:** 让用户通过平台真正删除正式记忆及全部可恢复正文派生物，只保留不可逆的 keyed HMAC 遗忘标记阻止旧来源重新生成，并允许用户通过新的审计事务显式恢复。

**Blocked by:** 08 — 有来源约束的 Graph Memory；14 — 重复、冲突与记忆替代

**Status:** ready-for-agent

- [ ] 用户可以从 Web 请求删除正式记忆并在执行前看到将受影响的正文、来源、索引、图关系和替代链。
- [ ] 删除事务移除权威正文、摘要、全文条目、embedding 和 Graph 投影，并形成新的 Git 提交。
- [ ] 遗忘标记只保存使用平台密钥生成的 HMAC 指纹、来源范围和删除时间，不保存明文、摘要、可逆散列或 embedding。
- [ ] 后续处理旧 Inbox、spool、会话来源或等价候选时，遗忘匹配阻止相同内容被自动重新创建。
- [ ] 遗忘标记不能跨不相关记忆库误伤内容，密钥轮换策略不会使既有标记静默失效。
- [ ] 普通和历史检索不返回已遗忘正文；Git 与平台展示不得提供绕过平台恢复流程的正文下载入口。
- [ ] 用户显式恢复时，平台从允许的本地 Git 历史创建新的权威版本和新提交，并更新或撤销对应遗忘约束。
- [ ] Docker 验收覆盖删除后各存储检查、图边清理、旧会话重放阻断、跨库隔离、恢复提交和服务重启。
