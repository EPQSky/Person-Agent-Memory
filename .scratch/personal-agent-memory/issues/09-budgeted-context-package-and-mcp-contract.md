# 09 — 10K 记忆上下文包与完整 MCP 检索契约

**What to build:** 将直接命中与有来源图扩展统一为可审计的记忆上下文包，通过服务端 tokenizer 强制执行动态预算，并向 MCP 客户端提供稳定、可降级的完整检索契约。

**Blocked by:** 08 — 有来源约束的 Graph Memory

**Status:** done

- [x] MCP 提供项目记忆搜索，并要求通过项目工作目录或显式项目记忆库标识确定范围。
- [x] 用户记忆库仅能通过显式 `library_id` 查询，默认项目查询不会联合或回退到用户库。
- [x] 每条返回结果包含内容、记忆库标识、文档路径、标题或行位置、来源类型、直接或图扩展分类、相关度、来源版本和降级状态。
- [x] 服务端按目标模型 tokenizer 计算整个记忆上下文包；不可用时使用保守 fallback，最终结果绝不超过请求预算或 10K tokens 硬上限。
- [x] 动态分配保证直接 Markdown 至少获得可用预算的 60%，图扩展最多 30%，来源与结构元数据最多 10%；未使用预算可回填直接命中。
- [x] 截断发生在完整结果边界或安全片段边界，不产生破损 JSON、Markdown 围栏或不可对应的来源记录。
- [x] 记忆内容被明确标记为不可信数据，响应契约不赋予其系统指令、工具授权或执行语义。
- [x] Docker 验收覆盖低预算、恰好 10K、超长单片段、多字节文本、图结果挤压、fallback tokenizer、显式用户库和未绑定项目。
