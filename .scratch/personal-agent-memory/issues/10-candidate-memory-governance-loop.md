# 10 — 候选记忆的人工治理闭环

**What to build:** 让 Codex 或其他 MCP 客户端只能创建候选记忆，并让用户在 Web 中检查、编辑、批准或拒绝候选；批准后生成正式权威 Markdown、刷新派生状态并形成可审计 Git 提交。

**Blocked by:** 05 — 平台编辑与隔离 Git 历史

**Status:** ready-for-agent

- [ ] MCP 提供候选创建、候选列表和单个候选查看能力，但不提供正式记忆的直接编辑、批准、删除或恢复。
- [ ] 候选记录包含稳定标识、建议类型、正文、来源引用、创建者、创建时间和当前状态。
- [ ] 候选不会出现在普通 Markdown、向量或 Graph 检索结果中，也不会改变 Codex 注入内容。
- [ ] Web 可以查看候选正文与来源、编辑拟发布内容、批准或拒绝，并记录操作者和理由。
- [ ] 批准候选后创建正式 Markdown，通过平台写入协调器形成一个 Git 提交，并触发直接索引更新。
- [ ] 拒绝候选不会留下正式正文、向量或图投影，但保留受保留策略约束的审批审计。
- [ ] 同一幂等键重复创建候选只产生一个候选，网络重试不重复发布或提交。
- [ ] Docker 浏览器与 MCP 验收覆盖创建、不可检索、编辑批准、拒绝、重复请求、重启恢复和 Git 提交内容。
