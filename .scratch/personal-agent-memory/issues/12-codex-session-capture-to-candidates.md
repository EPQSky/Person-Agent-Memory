# 12 — Codex 会话采集到候选记忆

**What to build:** 让全局 Codex 插件逐事件采集允许保留的用户消息和助手最终回复，通过幂等采集收件箱及本地 spool 承受中断，再由后台任务异步归并并生成可治理候选记忆。

**Blocked by:** 10 — 候选记忆的人工治理闭环；11 — Codex 全局插件的记忆召回

**Status:** done

- [x] UserPromptSubmit 和可用的助手完成事件分别采集用户消息与助手最终回复，并携带会话、项目、轮次、时间和幂等标识。
- [x] 默认采集不包含隐藏推理、原始工具输出、完整文件正文、子 Agent 内部轨迹或平台注入的记忆上下文。
- [x] 守护进程将事件写入采集收件箱，同一事件重试不会产生重复记录。
- [x] 守护进程不可用时 Hook 将允许的事件写入有大小和保留上限的本地 spool，并仍然成功退出。
- [x] 守护进程恢复后 spool 事件被安全重放并幂等接纳；损坏记录被隔离，不阻塞其他事件。
- [x] 后台任务按会话和轮次归并事件，异步调用提取模型生成候选，不增加 Codex 当前轮次等待时间。
- [x] PreCompact、SessionEnd 或后台空闲任务可触发幂等归并，但缺失这些事件不会丢失已采集轮次。
- [x] Docker 验收覆盖正常轮次、中途退出、重复事件、乱序事件、守护进程停机恢复、spool 上限、畸形事件及候选来源追踪。
