# 16 — 保留策略与隐私清理

**What to build:** 自动执行采集收件箱、候选、回收区、诊断记录和查询数据的保留政策，让用户能够固定、缩短或立即清理数据，同时保护未解决冲突和正式记忆来源的一致性。

**Blocked by:** 12 — Codex 会话采集到候选记忆；14 — 重复、冲突与记忆替代；15 — 真正遗忘、图清理与恢复

**Status:** ready-for-agent

- [ ] Inbox 原始事件默认保留 30 天；已成功提取且没有待处理候选依赖的事件可按策略提前清理。
- [ ] 未审批候选默认保留 90 天，随后进入 30 天可恢复回收区，再永久清理。
- [ ] 被用户固定或参与未解决冲突的候选不会因普通到期任务被清理。
- [ ] 用户可以按记忆库缩短保留期、触发立即清理并预览受影响数据类别。
- [ ] 原始检索查询默认不永久保存；诊断数据具有短期上限，可关闭并可立即清除。
- [ ] 清理任务不删除正式 Markdown、必要来源引用、Git 提交或 keyed HMAC 遗忘标记。
- [ ] 清理过程幂等、可中断恢复，并记录数量和错误而不把被清理正文复制到日志。
- [ ] Docker 验收使用可控时钟覆盖每个边界日期、固定记录、冲突记录、提前清理、重复执行和重启恢复。
