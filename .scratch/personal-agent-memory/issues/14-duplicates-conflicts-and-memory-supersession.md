# 14 — 重复、冲突与记忆替代

**What to build:** 让平台识别等价、疑似重复和相互冲突的候选，通过来源增补、人工合并或条件化裁决维护正式记忆，并用替代关系保留事实随时间变化的历史。

**Blocked by:** 13 — 敏感过滤与受控自动晋升

**Status:** ready-for-agent

- [ ] 明确等价的候选不会创建第二份正式正文，而是向已有记忆增补来源并形成一个原子 Git 提交。
- [ ] 相似但无法确定等价的候选进入人工合并队列，不自动拼接或覆盖内容。
- [ ] 与当前正式记忆冲突的候选不会自动晋升，并在 Web 展示双方正文、来源、时间和差异。
- [ ] 用户可以选择保留当前记忆、采用候选、合并为新版本或声明两者适用于不同条件。
- [ ] 新事实取代旧事实时创建带生效时间的 `supersedes` 关系，旧正文和来源仍可通过历史查询查看。
- [ ] 普通检索默认只返回当前有效版本；显式历史查询可以返回被替代版本及替代链。
- [ ] 每种裁决都是一个记忆变更事务，形成 Git 提交并使直接索引与 Graph 派生状态按新来源版本更新或失效。
- [ ] Docker 验收覆盖精确重复、语义重复、误判保护、直接冲突、条件并存、多级替代和重启后的替代链恢复。
