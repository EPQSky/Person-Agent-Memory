# 语义记忆与可浏览知识图谱

## Problem Statement

用户让 Codex 分析当前项目时，普通记忆检索会返回“用户: 帮我分析下当前项目”这样的原始提问。提问没有经过模型判断，也没有被提炼成适合长期保存的内容，却被当成记忆结果展示。用户无法区分“这段对话发生过”和“这是一条可用于后续工作的长期知识”。

管理台目前也缺少有效的浏览路径。记忆列表不明显，用户不能从列表进入完整详情；图谱只有状态和重建接口，没有节点、关系或查询子图。用户无法确认一条记忆为什么存在、来自哪段会话、关联了哪些实体，也无法浏览项目和领域的知识结构。

## Solution

把原始会话记录和正式语义记忆分开。原始会话记录只作为证据和审计来源，默认 REST、MCP 和 Codex 检索不返回原始 capture。一个完整回合在助手最终回复后异步提炼为零到多条原子语义记忆；每条记忆必须绑定用户原文证据。问题、临时计划、一次性输出和助手单独推断不发布。

管理台改为区域工作区。用户可以在“记忆”“图谱”“原始会话”之间切换，查看正式记忆列表，打开记忆详情，查看证据和关系，并在明确入口查看原始会话时间线。检索结果可以在实体知识图谱中定位。

知识图谱使用实体作为节点、受控类型的关系作为边，语义记忆作为证据层。图谱从正式记忆异步派生，只读、可重建、受节点和边上限约束。用户既可以浏览整库图，也可以查看以检索结果为种子的一跳或两跳查询子图。

## User Stories

1. 作为用户，我希望普通问题不会成为长期记忆，这样检索结果只包含可复用知识。
2. 作为用户，我希望一个完整回合可以生成零条语义记忆，这样没有长期价值的对话不会污染记忆库。
3. 作为用户，我希望一个完整回合可以生成多条原子语义记忆，这样每个事实都能独立治理。
4. 作为用户，我希望每条语义记忆表达一个完整、脱离对话仍能理解的主张，这样后续检索不需要重新猜测上下文。
5. 作为用户，我希望每条语义记忆显示支撑它的用户原文，这样我能核对模型是否改变了原意。
6. 作为用户，我希望助手回复不能单独成为用户事实，这样模型推断不会冒充我的陈述。
7. 作为用户，我希望语义提炼在后台异步发生，这样 Codex 回合不会被模型调用阻塞。
8. 作为用户，我希望会话结束或压缩前补跑遗漏的提炼任务，这样关闭会话不会丢失尚未处理的回合。
9. 作为用户，我希望模型失败时不发布正式记忆，这样错误或不可验证的内容不会进入长期记忆。
10. 作为用户，我希望采集失败保持 fail-open，这样记忆服务故障不会阻断编码工作。
11. 作为用户，我希望原始会话和正式记忆使用不同入口，这样我可以区分证据和知识。
12. 作为用户，我希望默认检索完全排除原始会话记录和旧的原样拼接单元，这样提问不会再次出现在记忆结果中。
13. 作为用户，我希望原始会话按会话和时间顺序查看，这样我可以追踪一段工作的上下文。
14. 作为用户，我希望原始会话显示由该会话提炼出的语义记忆链接，这样我能理解证据和知识之间的对应关系。
15. 作为用户，我希望原始会话视图首版不提供全文搜索，这样它不会被误用为正式记忆检索。
16. 作为用户，我希望正式记忆保留在当前项目、专题或用户区域，这样记忆边界仍然清楚。
17. 作为用户，我希望稳定个人事实可以晋升到用户区域，这样跨项目偏好保持一致。
18. 作为用户，我希望可泛化知识可以晋升到匹配的专题区域，这样专题知识可以被复用。
19. 作为用户，我希望项目特定事实留在项目区域，这样项目知识不会污染用户记忆。
20. 作为用户，我希望重复的语义记忆合并来源而不是重复正文，这样检索结果保持简洁。
21. 作为用户，我希望冲突的语义记忆不自动覆盖当前有效记忆，这样旧事实不会无声消失。
22. 作为用户，我希望敏感内容不进入正式记忆或图谱，这样凭据和隐私不会泄露。
23. 作为用户，我希望管理台默认显示正式记忆列表，这样原始对话不会淹没真正有价值的记忆。
24. 作为用户，我希望记忆列表显示摘要、类型、生命周期、更新时间和来源数量，这样我可以快速判断哪些值得查看。
25. 作为用户，我希望记忆列表支持分页，这样大记忆库仍能顺畅浏览。
26. 作为用户，我希望记忆列表支持按类型、生命周期和关键词筛选，这样我可以快速定位需要治理的记忆。
27. 作为用户，我希望点击记忆列表项打开详情面板，这样我不会只看到一行不透明的记忆标识。
28. 作为用户，我希望记忆详情显示完整正文、来源会话和证据片段，这样我可以核对记忆的真实来源。
29. 作为用户，我希望记忆详情显示版本和生命周期，这样我知道它是否仍有效、是否被替代或遗忘。
30. 作为用户，我希望记忆详情显示关联实体和关系证据，这样我能理解这条记忆在知识结构中的位置。
31. 作为用户，我希望记忆详情保留更正、遗忘和审计入口，这样查看详情后可以直接完成治理。
32. 作为用户，我希望管理台在选中区域后提供“记忆”“图谱”“原始会话”三个标签，这样不同用途的信息不会挤在同一长页面中。
33. 作为用户，我希望检索框位于区域工作区顶部，这样在记忆和图谱之间切换时不需要重新输入任务范围。
34. 作为用户，我希望检索结果出现在正式记忆列表中，这样我可以继续使用熟悉的列表和详情交互。
35. 作为用户，我希望检索命中可以在知识图谱中定位，这样我能看到结果之间的实体关系。
36. 作为用户，我希望整库知识图谱限制一次加载的节点和边数量，这样图不会因规模增长而失去可读性。
37. 作为用户，我希望整库图优先显示连接度高、最近更新和检索选中的实体，这样默认视图更有价值。
38. 作为用户，我希望可以按实体类型筛选图谱，这样我能聚焦技术、项目、概念或约束。
39. 作为用户，我希望可以搜索实体并渐进展开邻域，这样我可以按需浏览而不是一次加载全部知识。
40. 作为用户，我希望查询子图默认显示一跳关系，并允许展开到两跳，这样关联范围有界且可理解。
41. 作为用户，我希望直接命中、查询扩展和背景实体使用不同视觉状态，这样我能区分已知结果和联想结果。
42. 作为用户，我希望图谱默认只显示当前有效内容，这样我看到的是当前知识状态。
43. 作为用户，我希望可以显式打开历史视图，这样我能查看被替代或失效的关系。
44. 作为用户，我希望已遗忘记忆支撑的节点和边不再显示，这样真正遗忘在图谱中也成立。
45. 作为用户，我希望图谱节点和边可以回到支撑记忆和来源，这样图谱不是无证据的猜测。
46. 作为用户，我希望无法可靠实体化的事实保留在记忆列表而不是强行画进图谱，这样图不会产生虚假结构。
47. 作为用户，我希望实体名称按类型、规范名和明确别名识别，这样同类实体不会因文本拼写差异大量重复。
48. 作为用户，我希望不同类的同名对象保持独立，这样项目和同名概念不会错误合并。
49. 作为用户，我希望图谱不依据向量相似度自动合并实体，这样错误合并不需要事后拆分。
50. 作为用户，我希望关系类型来自固定词表，这样图谱可查询、可解释、不会出现同义关系名称。
51. 作为用户，我希望无法匹配固定关系的内容不建立边，这样图谱不会用弱关系填充。
52. 作为用户，我希望图谱是正式记忆的只读派生视图，这样图谱不会成为第二套知识真源。
53. 作为用户，我希望修改或遗忘正式记忆后，受影响图谱可以重建，这样图谱与记忆保持一致。
54. 作为用户，我希望图谱抽取失败时仍能使用直接记忆检索，这样模型故障不会使整个记忆平台不可用。
55. 作为用户，我希望图谱状态显示降级原因和重建入口，这样我可以判断问题来自模型、索引还是数据。
56. 作为用户，我希望普通检索图谱扩展只使用实体知识图谱，这样不会把关键词共现误认为语义关系。
57. 作为用户，我希望原始会话、正式记忆和图谱都标记为本地数据并受现有认证保护，这样新增浏览入口不会扩大安全边界。
58. 作为维护者，我希望回合提炼幂等，这样重复 Hook 或后台重试不会创建重复语义记忆。
59. 作为维护者，我希望图谱生成幂等，这样重复发布、重建或重启不会产生重复节点和边。
60. 作为维护者，我希望提炼和建图都有明确状态、错误和审计记录，这样后台失败可以诊断。
61. 作为维护者，我希望旧关键词关联图不继续作为用户图谱，这样项目只维护一种用户可见的图语义。
62. 作为维护者，我希望管理台交互有浏览器验收覆盖，这样“存在接口但页面看不见”的问题不会再次出现。

## Implementation Decisions

- 引入正式语义记忆作为默认可召回知识。原始 capture 和旧的原样拼接 `evolved` 单元继续保留用于证据、审计和迁移，但默认 REST、MCP 和 Codex 检索必须排除它们。现有 capture 事件可通过显式原始会话接口读取。
- 语义提炼以完整回合为单位。完整回合由同一 `turn_id` 的用户消息和助手最终回复组成。只有助手最终回复到达后才进入可提炼状态。缺失助手回复的回合保持待完成。
- 语义提炼在守护进程后台队列异步执行，不进入 Codex Hook 的请求预算。助手最终回复捕获成功后触发；会话结束和压缩事件负责补跑未完成、失败或遗漏的回合。Hook 仍保持 fail-open。
- 提炼结果为零到多条原子语义记忆。每条结果包含自包含正文、正式记忆类型、置信度、区域提示、用户证据事件标识和用户原文证据片段。问题、临时计划、一次性输出、隐藏推理、工具原始输出和助手单独推断不得成为结果。
- 证据校验使用原始用户事件的可定位文本。证据片段必须能在对应事件正文中确定性定位；缺失、空白或无法定位的证据使该条结果无效。助手回复只作为理解上下文，不作为用户事实证据。
- 语义记忆类型限定为决策、约束、偏好、领域事实、可复用经验和外部引用。区域提示只允许来源区域、用户区域或已存在的专题区域。无法确定目标时保留在来源区域，不允许模型创建新区域。
- 自动发布沿用现有证据和治理规则。置信度至少为 `0.90`、用户证据有效、类型允许、来源完整、无敏感内容、无未解决冲突且不是重复正文时，语义记忆进入正式记忆。低置信度、无效证据、冲突、敏感或模型异常时不创建正式记忆，并记录跳过原因。
- 重复语义记忆只增补来源引用，不复制正文。已有等价记忆时保留原正文和版本。存在冲突时当前有效记忆保持有效，冲突进入审计和治理流程，不由模型自动覆盖。
- 每条正式语义记忆保存提炼回合、证据事件标识、证据片段、来源区域、提炼时间和模型任务信息。重复处理同一回合必须幂等，不因 Hook 重放或后台重试生成重复记录。
- 原始会话接口按区域、会话和回合返回用户消息、助手最终回复、提炼状态、错误和已生成语义记忆标识。原始会话视图不提供全量全文检索，也不在首版提供重新提炼操作。
- 管理台在选中区域后提供三个工作区标签：“记忆”“图谱”“原始会话”。区域工作区顶部保留检索输入；搜索使用正式记忆范围，结果可进入记忆列表并用于图谱定位。
- 记忆列表默认只显示正式语义记忆，按更新时间倒序，每页 50 条。列表提供游标分页，并支持关键词、记忆类型和生命周期筛选。列表项包含摘要、类型、生命周期、更新时间和来源数量。
- 记忆详情使用当前页详情面板。详情包含完整正文、区域、类型、证据片段、来源会话、版本、生命周期、关联实体、关系证据，以及现有更正、遗忘和审计操作。
- 管理台新增正式记忆列表与详情读取契约，语义路径为 `GET /api/v1/libraries/{library_id}/memories` 和 `GET /api/v1/libraries/{library_id}/memories/{memory_id}`。列表契约支持 `cursor`、`limit`、`q`、`memory_type` 和 `lifecycle`。现有 document 接口可以保留兼容，但管理台不再用它作为主要列表入口。
- 原始会话视图使用现有 capture 接口的扩展契约，支持按 `region_id`、`session_id` 和 `turn_id` 读取回合与事件，并返回提炼状态和语义记忆链接。原始会话视图只读。
- 知识图谱实体类型固定为 `project`、`technology`、`component`、`concept`、`person`、`organization`、`constraint` 和 `reference`。关系类型固定为 `part_of`、`uses`、`depends_on`、`implements`、`has_constraint`、`prefers`、`references`、`supersedes` 和 `related_to`。模型不得创建词表外类型。
- 实体节点表示可识别对象，不把语义记忆正文默认作为节点。语义记忆是实体、关系和关系证据的来源层。无法可靠实体化的事实只保留在记忆列表。
- 实体身份由实体类型、规范化名称和明确别名组成。只有类型相同且规范化名称完全一致的实体自动合并。模型可以提出规范名和别名，但不得依据向量相似度、模糊拼写或跨类型同名自动合并。
- 知识图谱在正式语义记忆发布后异步生成。抽取输入限于正式记忆正文、已保存证据片段和区域信息。模型返回实体、固定类型关系和关系证据；确定性校验拒绝未知类型、悬空关系、无来源关系和敏感内容。
- 图谱节点和边必须稳定标识、幂等写入并保存支撑记忆标识和证据。图谱是只读派生投影，修正知识通过修改或遗忘正式记忆完成，再重建受影响部分；不提供直接编辑图数据的接口。
- 知识图谱读取契约提供整库有界图和查询子图。整库图默认最多 200 个节点和 400 条边，优先选择连接度高、最近更新和检索选中的实体。查询子图以检索命中的记忆或实体为种子，默认一跳，允许两跳，并标记直接命中、查询扩展和背景实体。
- 整库图支持实体类型筛选、实体搜索、渐进邻域展开和历史视图。历史视图弱化显示已替代或失效关系；已遗忘记忆支撑的节点和边不显示。
- 图谱不可用时，正式记忆检索仍返回直接命中并报告降级原因。用户可见图谱和图扩展不再使用关键词共现关系。旧关键词关联索引可以作为内部迁移诊断数据，但不得作为知识图谱返回。
- 图谱状态继续显示节点数、边数、已投影记忆数、待处理数、错误和重建状态。重新抽取或重建必须幂等，并在服务重启后收敛。
- 所有读取接口继续使用现有本地 API key 或管理台会话认证。原始会话、记忆详情和图谱数据保持单一本地用户边界，不引入远程共享、多用户权限或跨区域全图。

## Testing Decisions

- 好的测试验证用户可观察行为和持久化结果，不依赖私有方法调用顺序、内部表名或某个具体模型实现。
- 主测试缝使用现有 FastAPI `TestClient`，配合隔离状态目录、临时记忆区域、确定性语义提炼器和确定性图谱抽取器。测试直接断言 REST 响应、检索结果、持久化审计和重启后的状态。
- 服务缝必须覆盖：完整回合生成零条、一条和多条语义记忆；问题不生成正式记忆；助手单独内容不生成正式记忆；无有效用户证据不发布；低置信度、敏感、冲突和重复内容按既定规则处理。
- 服务缝必须覆盖：默认 REST 和 MCP 检索不返回 capture 或旧原样拼接单元；原始会话接口仍能读取这些记录；提炼任务幂等并能从重启或失败中恢复。
- 服务缝必须覆盖：正式记忆分页、筛选、列表摘要和详情字段；详情保留证据、来源、版本、生命周期和治理能力；已遗忘记忆不进入普通列表。
- 服务缝必须覆盖：图谱实体词表、关系词表、确定性实体身份、跨类型同名不合并、重复建图幂等、悬空关系拒绝、无证据关系拒绝和敏感内容拒绝。
- 服务缝必须覆盖：整库图节点和边上限、查询子图一跳和两跳、直接命中与扩展标识、历史视图、已遗忘内容隐藏，以及图谱故障时直接检索降级。
- Node Hook 子进程缝继续覆盖采集 fail-open、spool 重放和异步触发。测试不得等待真实模型或真实时间；使用可控队列、确定性完成信号或已有测试时钟。
- 模型客户端契约测试继续使用本地 OpenAI 兼容假服务，验证结构化输出请求、确定性采样参数、超时、重试和有界输出。解析或校验失败不得发布正式记忆或部分图谱。
- 新增 Playwright 浏览器验收缝。浏览器验收使用真实本地守护进程和管理台会话，配合确定性模型响应，验证“记忆”“图谱”“原始会话”标签可见且可切换，记忆列表可筛选和分页，点击记忆能打开详情，检索结果能定位查询子图，图谱显示节点边和降级状态。
- 浏览器验收优先使用可访问名称和用户操作定位元素，不依赖脆弱 CSS 层级。图的可视化断言检查节点、边、选中状态和错误提示，不比较像素截图。
- 现有 `tests/test_mem2_capture_evolution.py`、`tests/test_mem2_promotion.py`、`tests/test_mem2_graph.py`、`tests/test_memory_regions.py`、`tests/test_model_client.py` 和 `tests/test_codex_plugin.py` 提供测试先例。新增测试沿用临时状态、注入式模型和外部 HTTP 行为断言。
- 回归测试必须保持区域隔离、项目绑定、显式跨区域召回、10K token 预算、来源引用、敏感隔离、真正遗忘、原子审计、采集 fail-open 和回环监听边界。
- 测试优先验证高风险行为：问题误入记忆、原始内容进入默认检索、助手推断变成事实、图谱证据丢失、实体错误合并、已遗忘内容复现和 Hook 阻塞。

## Out of Scope

- 直接在管理台编辑、合并、拆分或隐藏图谱节点和边。
- 首版实体合并治理界面和别名管理界面。
- 原始会话全文搜索、原始会话重新提炼按钮和跨会话证据搜索。
- 会话级一次总结作为正式记忆。
- 助手回复单独证明用户事实。
- 低置信度内容进入新的独立人工审批队列。
- 用户自定义实体类型、关系类型或按供应商自定义抽取参数。
- 基于向量相似度的实体自动合并。
- 超过两跳的图谱浏览、图算法推理和无限加载全图。
- 跨区域联合知识图谱。
- 多用户、团队共享、远程访问、OAuth 或权限角色。
- 新增模型供应商、替换现有 OpenAI 兼容接口或改变模型密钥管理。
- 旧关键词图数据的语义迁移。旧数据只需被隐藏、降级或重建，不得作为用户可见知识图谱。
- 修改现有 30 天原始会话保留策略、真正遗忘语义或原子审计要求。
- 本次不承诺旧 `evolved` 原样单元的自动重新提炼；它们只在原始会话入口保留诊断可见性。
