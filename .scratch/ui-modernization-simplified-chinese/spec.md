# 管理界面现代化与简体中文化

## Problem Statement

作为个人智能体记忆平台的用户，当前管理界面将服务状态、记忆库注册、项目绑定、检索、候选记忆治理、敏感隔离、文档编辑、带外变更处理、本地历史、遗忘恢复和保留策略全部纵向堆叠在一个页面中。随着平台能力增加，用户需要反复滚动和寻找功能，难以快速判断系统当前状态，也难以区分高频工作与低频治理操作。

现有界面缺乏一致的信息层级、导航、状态反馈、空状态、加载状态和危险操作确认。表格、表单、编辑器与操作按钮只有最低限度的样式，不能清晰表达可用、禁用、处理中、异常和高风险等状态。在窄窗口中，密集表格和双栏工作区也容易降低可读性与操作效率。

界面文本目前主要使用英文，与目标用户期望的简体中文体验不符。部分技术状态直接显示后端原始值，用户需要自行推断含义；与此同时，路径、标识符、提交哈希和来源版本等可审计技术数据又必须保持原样，不能在翻译过程中失真。

用户需要一个更美观、清爽、专业且适合重复操作的本地管理工作台。它应参考字节跳动 Semi Design 一类中后台产品的克制设计语言，但保持项目本地优先、无外部运行时依赖和现有功能边界。

## Solution

将现有管理界面重构为桌面优先的应用工作台。认证后使用左侧导航、顶部状态栏和右侧工作区承载功能，登录后的默认页面为紧凑概览。高频功能“概览、记忆检索、候选审核、文档管理”直接进入一级导航；记忆库、项目绑定、敏感隔离、历史恢复和隐私设置统一归入“管理与治理”分组。

建立受 Semi Design 启发但不直接依赖其组件库的视觉系统。界面以白色和中性灰为基础，使用字节蓝作为主要交互色、青绿色表达正常与可用状态、橙色表达提醒、红色表达危险。控件采用紧凑一致的间距、边框、焦点、悬停、禁用和加载状态，避免营销式大卡片、装饰性渐变和过度动效。

界面主名称使用“个人智能体记忆”，并保留 `Personal Agent Memory` 作为英文副标识。所有面向用户的标题、按钮、字段标签、状态说明、空状态、成功消息、错误提示、确认对话框和无障碍标签改为简体中文。路径、记忆库标识、项目标识、提交哈希、来源版本、API 字段和值等技术数据保持原文，并使用中文标签和必要的中文状态映射帮助理解。

本次在现有原生 HTML、CSS 和 JavaScript 实现上完成改造，不改变后端 API、数据模型或记忆领域行为，也不引入外部 CDN。该选择是兑现既定 React 与 TypeScript 管理界面方向之前的过渡性改造；前端框架迁移作为独立后续工作处理。

## User Stories

1. 作为用户，我希望登录页直接显示“个人智能体记忆”，以便立即理解该工具的用途。
2. 作为用户，我希望英文产品名作为次要标识保留，以便仍能对应项目和服务名称。
3. 作为中文用户，我希望所有操作文案使用简体中文，以便不需要在中英文之间切换理解。
4. 作为用户，我希望登录说明清楚指出 API 密钥的位置和用途，以便顺利进入管理界面。
5. 作为用户，我希望认证失败时看到明确的中文错误信息，以便知道需要检查密钥。
6. 作为注重隐私的用户，我希望 API 密钥只保留在当前页面运行内存中，以便它不会出现在页面源码、URL 或浏览器持久存储里。
7. 作为用户，我希望认证后进入概览，以便快速判断服务和记忆系统是否正常。
8. 作为用户，我希望概览展示服务、数据库和后台任务状态，以便发现基础设施异常。
9. 作为用户，我希望概览展示记忆库数量、待审核候选数量和敏感隔离数量，以便决定下一步工作。
10. 作为用户，我希望概览突出索引异常和降级状态，以便优先处理会影响召回的问题。
11. 作为用户，我希望概览提供常用功能入口，以便减少重复导航。
12. 作为用户，我希望左侧导航始终表达当前位置，以便在多个治理模块之间保持方向感。
13. 作为用户，我希望高频功能位于一级导航，以便快速进入检索、审核和文档管理。
14. 作为用户，我希望低频治理功能分组展示，以便导航保持简洁但不隐藏能力。
15. 作为窄窗口用户，我希望导航可以收起，以便为主要内容留出足够空间。
16. 作为用户，我希望顶部状态栏持续显示服务连接状态，以便及时发现会话失效或服务异常。
17. 作为用户，我希望记忆库页面集中展示注册表信息和注册操作，以便管理所有记忆库。
18. 作为用户，我希望项目记忆库和用户记忆库用中文标签区分，以便正确选择记忆边界。
19. 作为用户，我希望记忆库的文本索引、图索引和可用性通过清晰状态徽标表达，以便快速扫描。
20. 作为用户，我希望路径、标识符和索引错误在有限空间内仍可完整查看，以便保留可审计性。
21. 作为用户，我希望空的记忆库列表提供明确空状态和注册入口，以便知道如何开始。
22. 作为用户，我希望项目绑定和 worktree 关联分别呈现，以便理解两种关系的差异。
23. 作为用户，我希望解绑或移除关联前获得确认，以便避免误操作改变默认召回边界。
24. 作为用户，我希望记忆检索页面突出工作目录和关键词输入，以便快速执行查询。
25. 作为用户，我希望检索时看到加载状态，以便知道请求正在处理而不是界面失效。
26. 作为用户，我希望未绑定项目、无结果和降级检索分别给出中文反馈，以便正确理解结果状态。
27. 作为用户，我希望搜索结果保留路径、行号、分类、图跳数和来源版本，以便核查召回依据。
28. 作为用户，我希望候选记忆页面采用列表与详情工作区，以便高效连续审核。
29. 作为用户，我希望候选状态筛选项使用简体中文，以便快速定位待处理内容。
30. 作为用户，我希望候选列表清楚区分待处理、已批准、已拒绝和置顶状态，以便掌握治理进度。
31. 作为用户，我希望候选详情清楚展示来源、治理原因、冲突和当前正式记忆，以便做出有依据的决定。
32. 作为用户，我希望批准、拒绝、保留、采用、合并和条件并存等动作使用准确的领域中文，以便避免错误裁决。
33. 作为用户，我希望敏感隔离记录与普通候选记忆在视觉和导航上分离，以便理解其更高的隐私风险。
34. 作为用户，我希望敏感内容被丢弃前看到明确确认，以便避免不可恢复的误操作。
35. 作为用户，我希望文档管理页面同时支持文档导航、Markdown 源文、预览和差异，以便完整管理权威记忆。
36. 作为用户，我希望编辑器标签页具有明确选中状态，以便知道当前看到的是源文、预览还是差异。
37. 作为用户，我希望未选择文档时看到有用的空状态，以便知道下一步需要从文档树选择内容。
38. 作为用户，我希望保存前仍需生成并查看差异，以便现有平台修改约束不因界面改造而弱化。
39. 作为用户，我希望保存中的按钮被禁用并显示进度，以便避免重复提交同一次修改。
40. 作为用户，我希望遗忘操作先展示所有影响范围，再进行强确认，以便理解对权威记忆及派生数据的影响。
41. 作为用户，我希望带外变更页面清楚区分基准、平台和外部内容，以便完成三方判断。
42. 作为用户，我希望冲突解决按钮只在所需信息完整时可用，以便避免提交无效决策。
43. 作为用户，我希望本地历史按时间和提交摘要易于扫描，以便选择需要检查的记忆版本。
44. 作为用户，我希望恢复操作明确显示文档路径和提交标识，以便确认恢复来源。
45. 作为用户，我希望恢复旧版本仍以新事务完成，以便界面优化不改变追加式审计行为。
46. 作为用户，我希望遗忘记忆与普通历史恢复明确分区，以便理解两种恢复入口的不同治理含义。
47. 作为用户，我希望隐私设置集中管理采集收件箱、候选、回收站和诊断保留天数，以便调整数据保留策略。
48. 作为用户，我希望清理预览以可读中文摘要展示影响数量，以便在执行前判断后果。
49. 作为用户，我希望立即清理和清除诊断使用危险样式及确认对话框，以便减少误触。
50. 作为用户，我希望所有表单具有一致的必填、焦点、错误和禁用状态，以便可靠完成输入。
51. 作为键盘用户，我希望可以使用合理的焦点顺序操作导航、表单、标签页和对话框，以便无需鼠标完成核心工作。
52. 作为使用辅助技术的用户，我希望图标按钮、状态和动态消息具有中文无障碍名称，以便理解和操作界面。
53. 作为用户，我希望加载失败时保留当前上下文并提供重试入口，以便暂时错误不会迫使我重新开始。
54. 作为用户，我希望成功和失败反馈靠近触发操作显示，以便知道反馈属于哪项工作。
55. 作为用户，我希望界面动效轻微且不妨碍操作，以便获得精致感而不降低效率。
56. 作为偏好减少动态效果的用户，我希望界面尊重系统的减少动态效果设置，以便避免不适。
57. 作为桌面用户，我希望表格、编辑器、列表和详情区域尺寸稳定，以便内容变化不会导致布局跳动。
58. 作为窄屏用户，我希望双栏区域转为单栏、表格可横向滚动，以便内容不重叠或溢出。
59. 作为本地优先用户，我希望界面字体、图标和样式不依赖公网资源，以便离线时仍完整可用。
60. 作为现有用户，我希望所有当前管理能力在改造后仍然存在，以便视觉升级不会造成功能回归。

## Implementation Decisions

- 本次保留现有原生 HTML、CSS 和 JavaScript 技术形态，不引入 React 构建链、组件框架或外部 CDN。
- 该实现是现状上的过渡性 UI 改造，不推翻已记录的 React 与 TypeScript 管理界面目标；框架迁移必须在后续独立规格中处理。
- 后端 REST 接口、请求载荷、响应结构、认证方式、记忆库注册表和领域状态机保持不变。
- 认证前使用独立的居中登录界面；认证后切换为包含侧边导航、顶部状态栏和主工作区的应用壳层。
- 登录后的默认视图为“概览”，以紧凑指标、异常提醒和常用入口呈现可从现有接口获得的信息。
- 一级导航为“概览、记忆检索、候选审核、文档管理”；“管理与治理”分组包含“记忆库、项目绑定、敏感隔离、历史恢复、隐私设置”。
- 页面视图在客户端切换，不引入新的服务端路由。当前视图可由内存状态管理，但不得把 API 密钥或敏感信息写入 URL 或持久化存储。
- 产品主名称为“个人智能体记忆”，英文副标识为 `Personal Agent Memory`。
- 所有用户可读文本使用简体中文，包括文档语言声明、页面标题、导航、标题、字段标签、选项、按钮、状态说明、空状态、加载提示、成功消息、错误消息、确认内容、工具提示和无障碍标签。
- 技术数据保持原文，包括路径、记忆库标识、项目标识、提交哈希、来源版本、接口错误细节和用户文档内容。已知枚举状态通过中文显示标签映射，但底层值不改变。
- 后端返回的可识别状态和错误应提供中文用户说明；无法安全分类的错误保留原始详情，同时增加中文错误上下文，不得吞掉诊断信息。
- 视觉系统以白色和中性灰为基础，字节蓝为主要交互色，青绿色为成功和可用状态，橙色为提醒，红色为危险与失败。不得使用大面积单色渐变、装饰性光斑或营销式英雄区。
- 使用统一设计令牌管理颜色、间距、字号、边框、阴影、焦点环、层级和动效时长，确保相同语义在所有模块中一致。
- 页面区块采用无额外装饰的工作区结构；卡片仅用于独立指标、重复项目、对话框或真正需要边界的工具，且不嵌套卡片。
- 控件圆角不超过 8px。表单控件、按钮、标签页、状态徽标和列表项具有稳定尺寸，不因加载文本或状态切换导致布局位移。
- 熟悉的工具动作优先使用图标按钮，并提供简体中文工具提示和无障碍名称；关键命令使用图标加文字。图标资产必须随应用本地提供。
- 动效仅用于视图切换、状态变化、加载和交互反馈，并尊重 `prefers-reduced-motion`。
- 所有异步操作必须表达待处理状态，防止同一操作重复提交，并在成功或失败后给出靠近操作位置的反馈。
- 每个数据视图必须区分初始空状态、筛选无结果、加载中、请求失败和正常数据状态。
- 危险操作统一使用模态确认对话框，不依赖浏览器原生确认框作为最终体验。对删除绑定、丢弃隔离记录、清理数据、遗忘记忆和恢复等动作展示具体对象及影响。
- 普通可恢复删除使用二次确认；遗忘及可能影响权威记忆与派生数据的高风险动作要求输入对象名称或明确确认短语。
- 候选记忆、敏感隔离、文档编辑和带外变更继续使用列表加详情的主从布局；窄屏时转换为单栏顺序布局。
- Markdown 源文、渲染预览和差异继续作为文档编辑器的三个标签页，保留保存前预览和来源版本并发校验。
- 表格在桌面宽度内优先保持可扫描的列；较长路径和标识符允许换行或省略，并提供查看完整值的方式。窄屏使用横向滚动，不挤压至不可读。
- 响应式设计以桌面管理工作为优先，不把移动端建设为独立产品目标。窄窗口必须保证导航可收起、主操作可触达、文本不遮挡、工作区不产生页面级非预期横向溢出。
- 本轮只实现浅色主题。深色主题所需颜色令牌可保持可扩展，但不交付主题切换或深色视觉验收。
- 本次不修改记忆领域词汇、权威记忆生命周期或治理规则，因此不需要更新领域词汇表或新增架构决策记录。

## Testing Decisions

- 测试只断言用户可观察行为、公共接口效果和安全属性，不断言 CSS 类名、内部辅助函数、具体 DOM 嵌套层数或像素级实现。
- 唯一新增测试接缝是真实浏览器中的管理界面。测试使用项目已有 Selenium 方式访问正在运行的本地服务，并通过用户可见控件完成操作。
- 浏览器验收覆盖认证成功、认证失败、中文应用壳层、默认概览、一级导航、治理分组和主要视图切换。
- 浏览器验收验证所有既有管理能力仍可从新信息架构进入，包括记忆库、项目绑定、检索、候选治理、敏感隔离、文档编辑、带外变更、本地历史、遗忘恢复和保留策略。
- 浏览器验收验证代表性异步流程的加载、成功、失败、禁用和重试状态，并确认重复点击不会产生重复提交。
- 浏览器验收验证候选审核、文档保存、冲突处理和恢复等现有关键工作流继续调用既有公共 API 并产生相同外部结果。
- 浏览器验收验证危险操作先出现中文确认界面，取消不会产生修改，确认后才执行请求；高风险操作还需满足明确确认条件。
- 浏览器验收以至少一个桌面视口和一个窄屏视口运行布局检查，确认导航、表格、主从布局、编辑器、按钮和对话框没有重叠、裁切或不可达操作。
- 视觉检查通过桌面与窄屏截图人工核对整体层级、配色、留白、状态区分和文本容纳，不建立逐像素快照或绑定浏览器渲染细节的基线。
- 浏览器验收验证键盘焦点可见、标签页和对话框可操作、图标按钮具有简体中文可访问名称。
- 浏览器验收验证减少动态效果媒体查询下不会执行非必要过渡。
- 安全验收继续确认 API 密钥、密钥指纹和平台目录不会预先嵌入页面，API 密钥不会写入 URL、`localStorage` 或其他持久化浏览器存储。
- 现有 FastAPI 页面契约测试继续用于确认管理界面可提供和敏感数据未泄露；其中英文界面文案断言更新为稳定的简体中文用户文案。
- 现有候选治理、敏感隔离和 Docker 浏览器验收是本次测试的优先先例。既有控件标识在没有充分理由时保持稳定，以降低功能回归和测试迁移风险。
- 不为配色值、间距值、阴影值或纯展示辅助函数编写低层单元测试。

## Out of Scope

- 将管理界面迁移到 React、TypeScript、Vite 或其他前端构建工具。
- 直接引入 Semi Design、Semi UI 或其他第三方组件库。
- 修改 REST、MCP、Codex Hooks 或后端数据契约。
- 修改记忆库注册、项目绑定、候选晋升、敏感治理、记忆替代、真正遗忘、历史恢复或保留策略的领域规则。
- 新增用户账号、多用户权限、远程访问或公网部署能力。
- 深色主题、主题切换器或用户自定义品牌色。
- 独立移动端应用或把移动端作为完整产品目标。
- 自动化逐像素视觉回归测试。
- 新增分析、遥测、第三方字体、外部图标 CDN 或任何需要公网才能渲染的资源。
- 对用户 Markdown 内容、技术路径、标识符、提交摘要或 API 原始值进行机器翻译。
- 为了匹配参考产品而复制字节跳动、飞书或 Semi Design 的商标、专有素材或完整页面布局。

## Further Notes

- “参考字节跳动”在本规格中指借鉴 Semi Design 一类中后台产品的清爽层级、精细状态、紧凑密度和克制动效，不代表像素级仿制或品牌冒充。
- 本次改造必须保持本地优先和离线可用。任何新增视觉资产均需随应用分发，并遵守其许可证要求。
- 中文化应使用领域词汇表中的规范名称，例如“记忆库”“项目记忆库”“用户记忆库”“候选记忆”“正式记忆”“带外变更”“记忆版本”和“遗忘标记”，避免用“知识库”等已明确排除的近义词。
- 规格发布后应使用 `$to-tickets` 拆分为可独立验证的纵向实施票据；本规格本身不具有 `ready-for-agent` 状态。
