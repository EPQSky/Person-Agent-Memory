# 02 — 依赖检查与 uv 自动引导

**What to build:** 在安装产生任何持久变更前判断当前机器是否满足发行边界。受支持环境继续安装；缺少 `uv` 时可在用户权限内自动补齐；缺少其他必需能力时停止并给出针对性的人工安装指引，不尝试提权或调用系统包管理器。

**Blocked by:** 01 — 受支持环境的一键安装

**Status:** ready-for-agent

- [ ] 安装器验证 Linux、x86_64 和可工作的用户级 systemd，不满足时在安装程序、插件或服务之前退出。
- [ ] 安装器验证项目支持范围内的 Python、Git、Node.js 和 Codex CLI，并对每类缺失或不兼容情况输出明确指引和非零退出状态。
- [ ] 已存在且可用的 `uv` 被直接复用，不执行不必要的下载或替换。
- [ ] 缺少 `uv` 时，安装器可在普通用户范围内自动安装并继续完成 Ticket 01 的完整安装流程。
- [ ] `uv` 自动安装失败时明确报告失败，不转而调用 `sudo`、系统包管理器或系统级安装路径。
- [ ] 任一前置检查失败后不存在部分安装的 Python 工具、Codex 插件或 systemd 服务。
- [ ] 自动化验收能够证明依赖检查、成功引导和失败分支均未调用 `sudo` 或常见系统包管理器。
