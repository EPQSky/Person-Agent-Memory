# 06 — 双版本发行验收与发布文档

**What to build:** 建立可作为 Linux Release 完成门槛的单一端到端验收入口，并交付面向用户的完整生命周期文档。发布资产应允许用户下载和审阅安装器、卸载器及匹配源码；Ubuntu 22.04 与 24.04 上的证据必须覆盖安装、真实 Codex 集成、升级、卸载和数据保护。

**Blocked by:** 02 — 依赖检查与 uv 自动引导；04 — 幂等重装与原地升级；05 — 保留数据的安全卸载

**Status:** done

- [x] GitHub Release 产物定义同时包含可独立下载审阅的安装器、卸载器和匹配源码归档，推荐流程不使用 `curl | sh`。
- [x] 一个端到端验收入口可在 systemd 可用的隔离普通用户环境中运行真实发行 wheel、Codex CLI、全局插件、用户服务、认证健康检查和真实 Hook。
- [x] 同一验收入口在 Ubuntu 22.04 和 Ubuntu 24.04 的 x86_64 环境通过，并明确区分“已测试发行版”与其他 systemd Linux 的能力兼容目标。
- [x] 验收覆盖默认安装、自定义目录、缺失 `uv` 引导、同版本重装、跨版本升级、普通卸载和 `--purge`。
- [x] 验收证明升级保留 API 密钥、平台状态与权威记忆，普通卸载保留平台状态，`--purge` 始终保留记忆库。
- [x] 验收证明完整生命周期不调用 `sudo` 或系统包管理器，不写入系统级服务位置，也不修改项目仓库状态或 Git remote。
- [x] 发布文档覆盖支持范围、下载与审阅、自动安装、手动 `uv tool install`、自定义目录、升级、普通卸载、`--purge`、服务管理、日志查看和备份责任。
- [x] 发布文档明确说明服务只随用户登录启动、不自动启用 linger、不自动打开浏览器，且 `.deb`、RPM、AppImage 和自动更新不属于本次发布。
- [x] 现有 Python 测试、静态检查、类型检查、原生安装测试及新增端到端验收全部通过后，才能宣告 Linux 安装发行流程完成。
