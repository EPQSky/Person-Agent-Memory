# GitHub issue tracker

Use GitHub Issues as the system of record. Preserve the repository's existing templates, labels, milestones, and automation.

Use `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, and `wontfix` for intake readiness. Implementation progress belongs in the issue body or the project's established project-board fields; do not invent a second status vocabulary without confirmation.

Before creating or changing issues, inspect the repository and use `gh` only when authentication and network access are available.
